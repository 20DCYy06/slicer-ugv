# 第一阶段 odom Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** 创建能在无设备 Noetic 环境验证的独立 odom 导航闭环。
**Architecture:** 两个包；已有 Slicer odom/scan/TF 输入，move_base + TEB 输出到 Guard raw 接口；标准 Action 作为唯一任务状态。
**Tech Stack:** ROS1 Noetic, Catkin, move_base 1.17.3, TEB 0.9.1, Python3 unittest/rostest。
**Spec:** docs/superpowers/specs/2026-10-23-odom-design.md

## Global Constraints

- 旧项目、队友树只读，禁止 Jetson/真实驱动/实车目标。
- 模型必须 network none、无设备、独立 master，明确 TEST_ONLY。
- 无 Session/Contract/Operations；生产不伪造 TF。
- 标准 MoveBaseAction，输入坐标必须可变换到 odom；无 map→odom。
- 不复制运行日志、bag、凭据、历史生成输入。

## Review Focus

- 空间未观测/窗口外目标必须拒绝，不把 unknown 当可行路。
- scan 失联必须停止，并允许有效输入恢复后在 patience 内续原目标。
- cancel 后没有任务重发者，不得自行恢复。
- namespace 改动必须正确解析 odom/scan/cmd_vel；外部 Guard 必须同步改 planner/costmap 参数。
- 模型 raw 速度与物理 Guard/Mux 链的验证边界必须明确。
