## 2. 已确定的首版范围

1. 仅实现室外 WGS84 目标输入。室内坐标方案尚未确定，保留清晰的导航适配边界即可，不实现未定的室内功能。

3. 电台提供局域网，双方使用 ROS1 节点通信。优先沿用当前 ROS 通信基础，使用清楚的消息结构与 topic，不引入 HTTP、MQTT 或新通信框架。
4. 车端只有一个逻辑任务指令来源：飞机侧统一出口。人工操作也先进入飞机侧接口，在飞机侧完成协调。车端不增加人工/飞机双源优先级、接管锁、控制租约或额外授权层。
5. 当前测试由电脑临时代替飞机。电脑工具必须使用将来飞机使用的同一消息类型、topic 和任务语义。
6. 同时只执行一个任务。一个任务包含最终停车点，以及可整体替换的有序途经点队列。
7. 多个独立任务排队以后再增加；首版没有独立任务 FIFO。
8. 反馈异步发布，不等待飞机 ACK，不依赖有人订阅或反馈成功，不因反馈拥堵拖住任务执行。
9. 继续经过现有导航与 Guard/Mux/Watchdog 链，不从任务接口直接发速度或 PWM。

## 3. 五种命令及行为

可采用以下操作名；若项目已有命名惯例可调整名字，但不得改变行为，实际名字必须与文档一致。

| 操作 | 必须实现的行为 |
| --- | --- |
| SET_TASK | 提交新的最终停车点及可选途经点。新任务替换原任务与原剩余途经点；原任务结束原因标明被替换。 |
| REPLACE_VIA_POINTS | 对当前未结束任务，整体替换所有未完成途经点，包括当前正在前往的途经点；保留最终停车点。 |
| PAUSE | 取消当前导航执行并按既有机制停车，保留任务和剩余路线。 |
| RESUME | 在既有运行条件满足时，从当前位置继续剩余路线；不回放旧轨迹。 |
| CANCEL | 停止执行，结束当前任务并清除其剩余路线；恢复命令不能复活已取消任务。 |

### 3.1 替换语义

- 原路线为 A → B → G，G 为最终目标。新途经点为 C、D 时，剩余路线变为 C → D → G；A、B 不再执行。
- 新最终目标为 H 时，原任务、原终点 G 与原途经点全部被替换，执行 H 或新任务随附的途经点后到 H。
- REPLACE_VIA_POINTS 的空列表表示取消全部剩余途经点并直接前往原终点；不表示暂停或取消。
- 先校验完整命令和整批坐标，通过后一次性提交替换。无效消息不能先清空或破坏原任务。
- 暂停期间允许更新终点或途经点，但保持暂停；只有明确 RESUME 才继续。
- 任务完成或取消后，迟到的路线更新不能重新启动任务。
- 必经点无法到达时，停止任务推进并报告原因；不默认跳点直接去最终目标。保留目标与剩余路线供改道或处置。
- 同一时刻只有一个有效导航执行。正确处理旧目标的取消、新目标提交及旧 Action 回调；不把“发出了取消请求”当成“旧执行已经结束”。
- 任务/路线已换代后，旧 Action 的成功、失败或取消结果不能让新路线跳点、完成或失败。

### 3.2 途经点与终点

- 途经点为位置通过语义：进入车端配置的通过范围即可推进；不要求指定 yaw，不增加定向、停留或完整终点地理复核。
- 朝向由现有规划与避障逻辑决定，可参考实际规划路径方向。不要将所有途经点填 yaw=0；不要只省略上层 yaw，却仍让底层对每个点执行不必要的最终姿态对准。
- 可以出现导航换段带来的减速或短暂停顿，首版不要求绝对不停顿；但不能将每个途经点都强制处理成完整停车目标。
- 最终停车点复用现有 Action、停车和地理复核，区分导航报告成功与最终到达已确认。
- 最终朝向未指定时采用已约定的接近方向策略；不要静默解释为世界方向零度。
- 到点与通过范围留在车端配置并写清实际值。不要为了使测试通过而同时放宽全部导航/定位容差。

## 4. 消息、顺序与异步状态

### 4.1 最小必要协议

- 采用清楚的 ROS 消息结构，复用合适的现有类型；需要自定义消息时提供队友可安装的最小接口包。
- 必须能识别操作类型、任务编号、请求编号/序号、最终目标与有序途经点。给协议一个明确版本。
- 同一请求重发只返回或发布原处理结果，不重复启动任务或重复加入途经点；同编号不同内容明确拒绝。
- 新旧命令顺序采用可说明的序号规则，允许跳号，不要求等待回执或补齐丢失版本。明确任务、发送端重启和序号的作用范围，避免旧消息重放。
- 任务命令不使用会在重连后自动重放运动的锁存行为。状态可以保留最新快照。
- 车端服务重启后不自动恢复旧运动；状态和恢复方式必须在文档中明确。
- 按本轮已定默认，通信中断本身不新增运动租约：车端在既有导航、定位与控制条件满足时继续最后已接受的任务；恢复通信后发布当前状态。

### 4.2 坐标

- 纬度/经度字段名称明确，单位为度，使用足够精度；直接复用现有 WGS84 转换与配准。
- 高度若提供，明确为椭球高；如果只提供经纬度，使用当前工程可说明的二维处理约定。不能把缺失高度默认为真实 0 m，也不能把飞机飞行高度当成地面目标高度。
- 已补偿到车辆参考点的目标不再补偿天线杆臂。
- 原始 WGS84 目标与转换后的导航目标均可公开，后者带实际 frame 与有效配准身份。定位/配准失效或重置遵循现行导航行为，不把旧局部坐标直接套入新配准。
- 不使用虚构经纬度做实车运动示例。电脑测试目标来自已保存的实地点或基于真实配准得到的合法测试点。

### 4.3 状态与反馈

至少公开：协议版本、当前任务编号、最近命令及处理结果、任务运行阶段、原始最终目标、转换后的当前导航目标及 frame、当前途经点、剩余途经点、暂停/失败原因、最近任务结果、状态更新时间，以及最终到达检查的必要结果。

- 状态区分已收到/已接受或拒绝、执行中、切换路线、暂停中/已暂停、到达复核、完成/失败/取消。可合并不必要枚举，但对外不能把接受当完成。
- 状态变化及时发布，周期发送最新快照；不要求每个历史反馈都被送达。
- 反馈使用有限、不会拖住任务调度的发送机制。无订阅者、慢订阅者或飞机掉线时，任务逻辑保持正常。
- 车内 Action 执行结果和取消结果用于状态推进；它们与是否收到飞机 ACK 无关。
- 后续屏幕只需订阅公开状态，不做屏幕 UI，也不要求读取日志文件才能拿到关键状态。

## 5. 导航接入与程序入口

## 6. 验证与部署

先完成针对性软件/ROS 联调，再部署，并在现场条件具备时用电脑发真实 ROS 指令执行短距离测试。无需重新跑与本轮无关的历史大回归。

必须覆盖以下可观察行为：

| 场景 | 验收要点 |
| --- | --- |
| 单个最终目标 | 命令受理、实际目标正确、执行状态可见、终点检查后才完成 |
| 多个途经点 | 按顺序位置通过，最终目标保持；不在途经点强制朝向对准或完整终点复核 |
| 运行中换途经点 | 含当前点的旧未完成列表被整体替换，原终点不丢 |
| 空途经点列表 | 正确转向原最终目标 |
| 运行中换终点 | 旧任务结束，新任务执行，旧回调不污染新任务 |
| 暂停后更新 | 终点/路线可变，车辆和任务仍暂停；恢复后执行更新后的路线 |
| 取消 | 确认停止并结束任务，旧消息、旧回调与 RESUME 不会复活任务 |
| 重复/旧序号/无效批次 | 不重复启动、不回退到旧路线、不破坏有效任务 |
| 无反馈订阅者/反馈中断 | 执行不等 ACK，恢复订阅能读到最新状态 |
| 重启/重连 | 旧锁存命令不自动恢复运动；当前状态和恢复策略可解释 |

- 纯状态机边界和旧回调问题优先在离线/假 Action 或隔离 ROS 环境验证，不为每个异常反复跑实车。

- 保留必要的命令、状态、实际 Action 目标/结果与定位/停车证据，能关联任务编号并回看发生顺序。
- 电脑代替飞机通过，表示电脑→ROS 通信→任务服务→导航的相应范围通过，不代表真实无人机端或全部电台工况已验收。
